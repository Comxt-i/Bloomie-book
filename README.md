# PUN AAN — แลกกันอ่าน แล้วคืนกัน

เว็บหาเพื่อนใกล้ตัวเพื่อแลกหนังสืออ่านชั่วคราว หนังสือยังเป็นของเจ้าของเดิม ไม่มีการโอนกรรมสิทธิ์หรือระบบชำระเงิน / ขนส่ง

หนังสือทุกแนวลงได้ โดยเริ่มจัดเป็น 7 หมวดใหญ่: นิยายและวรรณกรรม, การ์ตูนและมังงะ, ความรู้และพัฒนาตนเอง, การเรียนและสอบ, ธุรกิจและการเงิน, เด็กและเยาวชน, และอื่น ๆ ผู้ใช้เลือกหมวดที่สนใจตอนสมัคร และกรองตามหมวดได้ทั้งหน้าค้นหาและหน้าปัดหนังสือ หนังสือเรียนเดิมถูกจัดเข้า “การเรียนและสอบ” โดยยังเก็บชื่อวิชาเดิมไว้

## ขั้นตอนหลัก

1. สมัครสมาชิก ลงหนังสือของตัวเอง และเลือกพื้นที่ค้นหา
2. เลือกรัศมี 5–100 กม. แล้วปัดขวาเพื่อสนใจ / ปัดซ้ายเพื่อผ่าน มีปุ่มและคีย์บอร์ดใช้แทนได้
3. ถ้าสนใจหนังสือของกันและกัน เปิดแชทได้ทันที ถ้าสนใจฝ่ายเดียว ส่งคำขอแลกอ่านโดยระบุเล่มที่เสนอ จุดนัด วันนัด และระยะเวลาอ่าน
4. เมื่ออีกฝ่ายตอบรับ จองหนังสือทั้งสองเล่มและยกเลิกคำขอที่ชนกัน เปิดแชทนัดหมายได้
5. ทั้งสองฝ่ายยืนยันได้รับหนังสือแล้ว จึงเริ่มช่วงอ่านและคำนวณกำหนดคืน
6. เจ้าของแต่ละคนยืนยันได้รับเล่มของตัวเองคืน เมื่อครบสองฝ่ายจึงปิดรายการและเปิดให้แลกอ่านอีกครั้ง

ยกเลิกได้ก่อนมีฝ่ายใดยืนยันรับหนังสือ การรับ/คืนซ้ำและการเปลี่ยนสถานะโดยคนอื่นจะถูกปฏิเสธ หนังสือที่กำลังอ่านไม่สามารถถูกนำไปจองซ้ำได้

## ตำแหน่งและแชท

- ขอสิทธิ์ตำแหน่งเมื่อผู้ใช้กดปุ่มเองเท่านั้น หรือระบุพิกัดจุดนัดพบด้วยตนเองได้
- ปัดพิกัดเหลือสองตำแหน่งทศนิยม เก็บเพียงพื้นที่ปัจจุบันที่เลือก ไม่มีประวัติการเคลื่อนที่ และลบพื้นที่ได้
- คนอื่นเห็นเฉพาะระยะห่างโดยประมาณ ไม่ได้รับพิกัด อีเมล หรือข้อมูลบัญชีของเจ้าของหนังสือ
- ระยะเป็นเส้นตรงจากพื้นที่โดยประมาณ ไม่ใช่ระยะเดินทางจริง
- แชทเปิดได้เมื่อสนใจตรงกันหรือมีคำขอที่ตอบรับแล้ว ตรวจสมาชิกห้องทุกครั้งที่อ่าน/ส่งข้อความ แชทอัปเดตทุก 5 วินาทีเมื่อหน้าเปิดอยู่ แสดง 100 ข้อความล่าสุด

## เริ่มใช้งาน

ต้องมี Node.js 20+ และ Python 3.12+ สำหรับส่วน ML

```bash
npm install
npm --prefix client install
npm --prefix server install
cp server/.env.example server/.env
npm run dev
```

เปิด http://localhost:4173

บัญชีสาธิต `natcha@demo.com` และ `kanittha@demo.com` ใช้รหัสผ่าน `demo1234` ทั้งคู่ ตำแหน่งสาธิตอยู่บริเวณหาดใหญ่ (ไม่ใช่ตำแหน่งจริงของผู้ใช้) เปลี่ยนพื้นที่จากเมนูได้ ข้อมูลในโหมดสาธิตหายเมื่อปิด API

## ระบบแนะนำ Python / scikit-learn

```bash
python3 -m venv ml/.venv
ml/.venv/bin/python -m pip install -r ml/requirements.txt
npm run dev:ml
```

เมื่อติดตั้ง Python แล้ว ใช้ `npm run dev:ai` เพื่อเปิดเว็บ, API และ ML พร้อมกันในเครื่องเดียวได้ ตรวจ `http://127.0.0.1:4190/health` ว่าตอบ `content-knn`

เปิดบริการ ML ควบคู่กับ `npm run dev` Node ส่งเฉพาะชื่อและหมวดหนังสือ ความสนใจ ระดับการศึกษาเดิม (ถ้ามี) และระยะโดยประมาณ ไม่ส่งพิกัด ชื่อผู้ใช้ อีเมล หรือข้อความแชท

- กรองหนังสือที่พร้อมแลกภายในรัศมีก่อน
- ระยะเริ่มต้นใช้ content-based KNN (NearestNeighbors + cosine distance) กับ TF-IDF character n-grams ของชื่อ หมวด และหนังสือที่เคยกดสนใจ รองรับข้อความภาษาไทยโดยไม่อาศัยการเว้นวรรค
- หน้า “ค้นหาเล่มถัดไป” และหน้าปัดหนังสือใช้บริการจัดอันดับเดียวกัน หน้าแรกใช้ content-KNN เพราะไม่มีข้อมูลระยะทางของทุกเล่ม ส่วนหน้าปัดสามารถใช้โมเดลที่ฝึกแล้วเมื่อมีข้อมูลและเปิดใช้งานโมเดล เหตุผลรายเล่มระบุเฉพาะสัญญาณที่ตรวจได้ เช่น หมวดที่สนใจหรือหมวดเดียวกับเล่มที่เคยกดชอบ ไม่อ้างว่าเป็นคำอธิบายภายในโมเดล
- KNN ค้นหาความคล้ายคลึงนี้ไม่ใช่โมเดลที่เรียนจากผลการแลกจริง และไม่แสดงเปอร์เซ็นต์ความแม่นยำ
- ถ้าบริการ Python ไม่ทำงาน ระบบสำรองใช้ความสนใจและระยะทาง พร้อมระบุ engine ใน API ไม่มีการแอบอ้างว่าใช้ ML สำเร็จ
- ระบบเก็บ feature snapshot และ Like/Dislike ใน `swipe_events` เพื่อทำ supervised learning เมื่อมีข้อมูลจริงเพียงพอ

### เปรียบเทียบโมเดลที่เรียน

ส่งออกข้อมูลจาก PostgreSQL ด้วยคำสั่งภายในเครื่อง ไม่มี endpoint สาธารณะสำหรับชุดฝึก:

```bash
cd server
node src/export-swipes.js ../ml/swipes.json
cd ..
ml/.venv/bin/python ml/train.py ml/swipes.json --output ml/models
```

เปรียบเทียบ KNN classifier, Decision Tree และ Logistic Regression โดย deduplicate คู่ผู้ใช้/หนังสือ แบ่งผู้ใช้ไม่ซ้ำกันใน training/validation/test 60/20/20 เลือกด้วย validation F1 และประเมิน test เพียงครั้งเดียว มี Precision, Recall, F1 และ Precision@5 / Recall@5 บนหนังสือที่มีการปัดเท่านั้น ไม่ใช่ทั้งคลังและไม่ใช่ผลความสำเร็จในการคืนหนังสือ

ต้องมีอย่างน้อย 100 คู่ที่ปัดจากผู้ใช้ 15 คนและสอง label ทุก split ถ้าข้อมูลไม่พอจะหยุดโดยไม่สร้างโมเดลหรือค่าความแม่นยำ ไม่มีการสร้างข้อมูลจำลองเพื่ออ้างผลจริง

### ทดลองเทรนด้วยข้อมูลจำลอง

ถ้าต้องการทดลองขั้นตอนการเทรนก่อนมีผู้ใช้จริง ให้รัน:

```bash
ml/.venv/bin/python ml/demo_train.py
```

สคริปต์สร้างการกดสมมติ 600 รายการจากผู้ใช้สมมติ 30 คน แล้วฝึก KNN classifier, Decision Tree และ Logistic Regression ผลลัพธ์อยู่ใน `ml/models/synthetic-demo/` ซึ่ง Git ไม่ติดตามและไม่เขียนลง PostgreSQL รายงาน `evaluation.json` กับโมเดลติดป้าย `synthetic-demo` ชัดเจน ตัวเลขประเมินบอกเพียงว่าโมเดลทายกฎที่ใช้สร้างข้อมูลปลอมได้แค่ไหน **ไม่ใช่ความแม่นยำกับผู้ใช้จริง** สคริปต์จะไม่เขียนทับโฟลเดอร์เดิม; หากต้องการทดลองใหม่ให้กำหนด `--output` เป็นโฟลเดอร์ใหม่

โมเดลจำลองไม่ถูกโหลดโดยปริยาย หากจะทดลองกับแอปในเครื่องเท่านั้น ใช้ `ALLOW_SYNTHETIC_MODEL=1 ML_MODEL_PATH=ml/models/synthetic-demo/selected.joblib npm run dev:ai` หน้าจอจะระบุว่าเป็นโมเดลสาธิต ห้ามนำผลนี้ไปอ้างในการ deploy จริง

ใช้โมเดลที่ฝึกเองด้วย `ML_MODEL_PATH=ml/models/selected.joblib npm run dev:ml` อย่าโหลดไฟล์โมเดลจากแหล่งที่ไม่เชื่อถือ ไฟล์ข้อมูลฝึกและโมเดลถูกละเว้นจาก Git

## PostgreSQL

ตั้งค่า `DATABASE_URL` และ `JWT_SECRET` ใน `server/.env` จากนั้นเริ่ม API ตารางพื้นฐานมาจาก `schema.sql` และส่วนเพิ่มเติมจาก `reading-schema.sql` เก็บรายการเก่าไว้โดยไม่เปลี่ยนเจ้าของหนังสือหรือเปิดเล่มที่เคยแลกถาวรกลับมาเอง

## Deploy บน VM เครื่องเดียว

ชุด `compose.yaml` ใช้ Caddy เสิร์ฟเว็บและ HTTPS, Node API, PostgreSQL แบบเก็บข้อมูลใน volume และ Python ML ในเครือข่าย Docker ภายใน เปิดออกสู่สาธารณะเฉพาะพอร์ต 80/443 โมเดลจากข้อมูลจำลองจะไม่ถูกนำขึ้นไปด้วย; ML เริ่มจาก content-KNN

1. เตรียม VM ที่ติดตั้ง Docker Engine และ Docker Compose, ชี้ DNS ของโดเมนมาที่ IP ของ VM และเปิดพอร์ต TCP 80/443 (UDP 443 เป็นตัวเลือกสำหรับ HTTP/3)
2. นำโค้ดขึ้น VM แล้วสร้างไฟล์ secret จากตัวอย่าง:

   ```bash
   cp .env.deploy.example .env.deploy
   openssl rand -hex 32
   openssl rand -hex 32
   ```

   ใส่ค่า random สองชุดที่ต่างกันใน `POSTGRES_PASSWORD` และ `JWT_SECRET` ของ `.env.deploy` ตั้ง `APP_DOMAIN` เป็นชื่อโดเมนจริง **ไม่มี** `https://` นำหน้า รหัสผ่าน PostgreSQL ต้องเป็นอักษรแบบ URL-safe เช่น hex เพราะ Compose นำไปประกอบใน `DATABASE_URL` อย่า commit ไฟล์นี้ และจำกัดสิทธิ์ด้วย `chmod 600 .env.deploy`
3. ตรวจไฟล์และเริ่มบริการ:

   ```bash
   docker compose --env-file .env.deploy config --quiet
   docker compose --env-file .env.deploy up -d --build
   docker compose --env-file .env.deploy ps
   ```

4. เปิด `https://<APP_DOMAIN>` และตรวจ `https://<APP_DOMAIN>/api/health` ต้องได้ `storage: "postgresql"` บริการ ML ตรวจได้จากภายในด้วย `docker compose --env-file .env.deploy exec ml python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:4190/health').read().decode())"`
5. ก่อนเปิดรับผู้ใช้จริง สมัครบัญชีทดสอบ ลงหนังสือหนึ่งเล่ม แล้ว `docker compose --env-file .env.deploy restart api` เพื่อตรวจว่าบัญชีและหนังสือยังอยู่ จากนั้นทำ backup และลองกู้คืนบนฐานข้อมูลแยก

ถ้าเริ่มไม่สำเร็จ ใช้ `docker compose --env-file .env.deploy logs --tail=100 api ml web db` เพื่อตรวจข้อผิดพลาด Caddy ขอและต่ออายุใบรับรอง HTTPS ให้เมื่อ DNS/พอร์ตพร้อม หน้าเว็บส่ง `/api` ผ่าน Caddy ไปยัง API จึงไม่พึ่ง Vite dev proxy ใน production บริการ API จะไม่เริ่มในโหมด production หากไม่มีฐานข้อมูล, `JWT_SECRET` ที่แข็งแรง หรือ origin แบบ HTTPS

ก่อนอัปเดตระบบ ให้สำรองฐานข้อมูลอย่างน้อยหนึ่งชุดและทดสอบกู้คืนบนฐานข้อมูลแยก:

```bash
install -d -m 700 backups
docker compose --env-file .env.deploy exec -T db sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > "backups/punaan-$(date +%Y%m%d-%H%M%S).sql"
```

โฟลเดอร์ `backups/` ถูกละเว้นจาก Git แต่ควรเก็บสำเนานอก VM ด้วย Volume ของ Docker ช่วยให้ข้อมูลอยู่ต่อหลัง recreate container แต่ **ไม่ใช่** backup ก่อนเปลี่ยน schema ของฐานข้อมูลจริงควรสำรองและทดสอบการกู้คืนเสมอ อย่าใช้ `docker compose down -v` กับระบบที่มีข้อมูลจริง เพราะจะลบ volume
